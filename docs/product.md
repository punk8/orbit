# 目标产品形态与功能

## 产品定位

Orbit 是一个本地优先的个人工作上下文系统。它在用户授权范围内观察日常工作，把零散事件整理成可追溯的 Activity、Knowledge、Memory、Recommendation 和 Handoff，帮助用户在跨天、跨工具、跨项目时保持上下文连续。

Orbit 不是某一个应用的附属功能，也不是截图搜索工具。具体数据源都只是可替换的 Source Adapter；产品核心是理解、沉淀、检索和交接工作上下文。

## 产品承诺

Orbit 应帮助用户回答：

- 今天我做了什么，证据来自哪里？
- 哪些讨论、决策、代码变化、问题排查和待办值得回顾？
- 哪些项目事实、偏好、决策或稳定模式应该成为长期记忆？
- 哪些风险、遗漏、阻塞和跟进事项需要我注意？
- 下一个 Agent 接手前应该知道什么？
- Orbit 读了什么、保存了什么、总结了什么、删除了什么、导出了什么？

## 核心功能

### Today

今日工作入口。展示当天 Activity、Knowledge、Memory candidate、Recommendation、来源状态和简短日报。

要求：

- 重要结论都能跳回来源证据。
- 不把未确认 Memory 当成事实。
- 明确展示来源是否暂停、失败、被隐私策略阻止或不可导出。

### Activity

证据层。由一组相关 Event 聚合成工作片段，负责回答“发生了什么”。

要求：

- 按时间、项目、应用、来源和敏感级别浏览。
- 展示事件数量、来源、时间段、本地存储状态和可用证据。
- 可以关联由它生成的 Knowledge、Memory 和 Recommendation。

### Knowledge

可审阅知识层。把 Activity 归纳为日报、会议纪要、排障总结、决策记录、项目背景、问题脉络等文档。

要求：

- 支持编辑、确认、拒绝、归档、搜索和导出。
- 每个关键结论保留 evidence ref。
- 只有确认后的 Knowledge 才能默认参与长期 Memory 和 Handoff。

### Memory

长期记忆层。保存更小、更稳定、适合检索和注入 Agent 上下文的事实。

要求：

- Memory candidate 默认进入审阅队列。
- 支持项目范围、标签、置信度、有效期、证据、版本历史、归档和删除。
- 默认只把 confirmed/active Memory 放进 Agent 上下文。

### Recommendation

主动建议层。发现待跟进、风险、阻塞、遗漏、重复模式或上下文缺口。

要求：

- 每条建议必须包含依据、置信度、影响范围和建议动作。
- 默认不执行外部副作用。
- 支持接受、忽略、稍后提醒和标记完成。

### Handoff / Agent Interface

交接层。为 Codex、Claude Code 或其他本地 Agent 提供只读上下文包。

要求：

- 支持 Today 和 Project 两类 Handoff。
- 输出 Markdown 和 JSON。
- 默认排除 draft Knowledge、未确认 Memory、raw 私密内容、截图、音频、转写原文和不可导出来源。

### Sources

来源管理。所有输入都必须显式配置、可暂停、可删除、可查看权限边界。

目标来源：

- 本地明确路径：Codex session、local agent session、用户导入包、项目目录、笔记和日志。
- 桌面观察：应用/窗口变化、Accessibility 文本、文件活动、终端活动、剪贴板，均需授权。
- 高风险感知：Screen/OCR、音频、转写、视觉摘要，必须单独授权、可见运行、可暂停、短保留、可清理。
- 工作系统：日历、邮件、文档、会议、代码仓库、任务系统、IM/协作工具。

## 非目标

- 不默认后台录屏。
- 不默认读取私人聊天、邮件、屏幕或文件系统。
- 不把原始数据备份当作核心价值。
- 不在未授权情况下发消息、改代码、建任务或执行外部副作用。
- 不为了演示体验内置样本数据作为用户默认数据。
